# Split-tunnel для приложений Nelomai

Дата: 30 июля 2026 года

Статус: согласованная спецификация перед составлением плана реализации.

## Цель

Добавить управляемый split-tunnel в приложения Nelomai, сохранив минимальную
нагрузку на устройство и возможность подключения при временной недоступности
панели.

Первая версия должна:

- направлять выбранные адреса вне VPN на Android, Windows, Linux и macOS;
- управлять маршрутизацией отдельных приложений на Android;
- применять split-tunnel при подключении `Tic + via_tak` и при любом
  подключении к Stray;
- получать правила из панели, но хранить последнюю рабочую политику локально;
- поддерживать централизованные обязательные исключения и рекомендации;
- безопасно применять новые правила с восстановлением предыдущего подключения
  при ошибке.

## Термины

- **Политика** — версия набора правил split-tunnel для конкретного устройства.
- **Обязательное исключение** — Android-приложение с точным совпадением package
  ID, которое всегда работает вне VPN и не может быть возвращено пользователем
  в туннель.
- **Рекомендация** — установленное Android-приложение, в отображаемом имени
  которого найден заданный администратором фрагмент. Пользователь сам принимает
  или отклоняет рекомендацию.
- **Пользовательское правило** — выбор приложения, сделанный пользователем на
  конкретном устройстве.
- **Адресное исключение** — сеть или адрес, который должен идти напрямую, минуя
  VPN.
- **Обычная ревизия** — номер последнего изменения правил без требования
  немедленного применения.
- **Принудительная ревизия** — номер изменения, которое должно быть получено и
  применено всеми запущенными приложениями при ближайшем опросе.

## Режимы

На устройстве доступно два режима:

1. **Исключать выбранные приложения** — выбранные приложения работают напрямую,
   остальные используют VPN. Это режим по умолчанию.
2. **Только выбранные приложения через VPN** — выбранные приложения используют
   VPN, остальные работают напрямую.

Отдельного пользовательского режима полного отключения split-tunnel нет.
Обязательные приложения и адресные исключения применяются всегда, когда
split-tunnel активен для выбранного типа подключения.

В режиме «Только выбранные приложения через VPN»:

- обязательные исключения нельзя выбрать для работы через VPN;
- сохранение пустого списка разрешено;
- запуск подключения с пустым списком блокируется понятным сообщением:
  «Выберите хотя бы одно приложение для подключения через VPN».

Приоритет правил, от высшего к низшему:

1. обязательное исключение по точному package ID;
2. пользовательское правило;
3. рекомендация по фрагменту отображаемого имени.

Если приложение одновременно совпало с обязательным package ID и с
рекомендацией по имени, рекомендация для него не показывается.

## Условия активации

Split-tunnel активен:

- при подключении к Tic с маршрутом `via_tak`;
- при любом подключении к Stray.

При подключении к Tic в режиме `standalone`:

- адресные исключения не применяются;
- правила отдельных приложений не применяются;
- привилегированный компонент получает обычную конфигурацию туннеля без
  split-tunnel;
- обязательные Android package ID не исключаются из standalone-туннеля.

Политика Tic при этом продолжает синхронизироваться и кешироваться. Пользователь
может заранее изменить настройки, но приложение показывает, что они начнут
действовать при подключении через Tak.

Переход активного подключения между `via_tak` и `standalone` считается
изменением эффективной политики и выполняется через обычный безопасный
stop/start. При переходе в `standalone` созданные Nelomai прямые маршруты должны
быть удалены; при возвращении в `via_tak` последняя сохраненная политика
применяется снова.

Для слоя Tic значение `route_mode=standalone` отключает split-tunnel. У Stray
то же значение является только техническим режимом маршрута, поэтому
split-tunnel для Stray применяется всегда. Клиент определяет активность по
сочетанию слоя и маршрута, а не только по полю `route_mode`.

## Этапы поддержки платформ

### Первый этап

- Android: адресные и прикладные правила.
- Windows: адресные правила.
- Linux: адресные правила.
- macOS: адресные правила.

На Windows и Linux элементы выбора приложений до реализации второго этапа не
показываются. На macOS прикладной split-tunnel не планируется в текущей схеме
распространения: он требует Apple Network Extension entitlement и официального
подписанного канала распространения.

Адресные правила из существующих «Фильтров блока» на первом этапе сохраняют
текущую IPv4-семантику панели. Селективное исключение IPv6-адресов не входит в
этот этап и не должно незаметно подменяться исключением всех IPv6-маршрутов.

### Второй этап

- прикладные правила на Windows;
- прикладные правила на Linux.

Он выполняется после проверки первого этапа на реальных устройствах. Протокол
между приложением и привилегированным компонентом сразу делается версионным,
чтобы второй этап не требовал ломать контракт.

## Архитектура

Панель является источником структурированной политики. Она не формирует
гигантский итоговый `AllowedIPs` для приложения и не заставляет клиент
самостоятельно разрешать домены из фильтров.

Панель хранит:

- глобальный флаг доступности функции;
- обязательные Android package ID;
- рекомендуемые фрагменты названий;
- настройки и выбор пользователя по каждому устройству;
- обычную и принудительную ревизии;
- текущую агрегированную статистику выборов;
- историю добавления и удаления пользовательских правил;
- последний результат применения политики устройством.

Для конкретного устройства панель формирует готовую политику:

- версию формата;
- обычную и принудительную ревизии;
- хеш эффективного содержимого;
- режим устройства;
- настройку исключения локальных сетей;
- обязательные package ID;
- рекомендации;
- пользовательские package ID;
- рассчитанные IPv4 CIDR из активных глобальных, пользовательских и
  привязанных к пиру «Фильтров блока»;
- время формирования.

Приложение объединяет политику с локальным списком установленных приложений и
при `Tic + via_tak` либо Stray передает привилегированному компоненту только
готовые списки пакетов и маршрутов. При `Tic + standalone` эти параметры не
передаются. Полный список установленных приложений остается на устройстве.

## Контракт API

Конкретные имена могут быть согласованы с существующим стилем маршрутов панели,
но контракт разделяется на четыре операции:

1. `GET /api/app/split-tunnel/revision` — дешевый запрос текущих обычной и
   принудительной ревизий и глобального флага.
2. `GET /api/app/split-tunnel/policy` — получение полной эффективной политики
   для авторизованного устройства.
3. `PUT /api/app/split-tunnel/settings` — сохранение режима, настройки локальных
   сетей и выбранных package ID этого устройства.
4. `POST /api/app/split-tunnel/apply-result` — результат применения: ревизия,
   хеш, время, успех или нормализованный код ошибки.

Пример полной политики:

```json
{
  "format_version": 1,
  "enabled": true,
  "revision": 14,
  "force_revision": 2,
  "policy_hash": "sha256:...",
  "mode": "exclude_selected",
  "exclude_local_networks": true,
  "mandatory_excluded_packages": ["ru.ozon.app.android"],
  "suggested_name_fragments": ["Яндекс", "MAX", "Ozon"],
  "selected_packages": ["com.example.application"],
  "excluded_ipv4_cidrs": ["203.0.113.0/24"],
  "generated_at": "2026-07-30T12:00:00Z"
}
```

При сохранении пользовательских настроек панель сразу возвращает новую
эффективную политику. Это изменение не ожидает суточной фоновой синхронизации.

Все маршруты приложения требуют действующую сессию приложения и проверенную
привязку устройства. Настройки одного устройства нельзя прочитать или изменить
с другого устройства только по переданному идентификатору.

## Android: обнаружение приложений

При первом открытии настроек split-tunnel приложение сканирует установленные
приложения. Обычные приложения показываются сразу, системные доступны через
переключатель «Показать системные».

Для получения списка применяется Android package visibility с необходимым
разрешением. Приложение распространяется вне Google Play, но полный список все
равно считается чувствительными локальными данными:

- он не отправляется в панель;
- не попадает в диагностические логи;
- не сохраняется в открытом виде дольше, чем необходимо локальному интерфейсу.

Android использует нативные возможности `VpnService.Builder`:

- `addDisallowedApplication` для режима исключений;
- `addAllowedApplication` для режима «Только выбранные через VPN».

Одновременно используется только один из этих способов, как требует Android
API. Итоговый `AllowedIPs` для адресных исключений не вычисляется: при большом
числе фильтров это раздувает конфигурацию и повторяет недостаток существующего
панельного split-tunnel.

На Android 13 и новее Nelomai регистрирует собственный `VpnService`, наследующий
`GoBackend.VpnService` из закрепленной WireGuard Android-зависимости. Сервис
возвращает специализированный `VpnService.Builder`, который непосредственно
перед `establish()` применяет компактный список IPv4 CIDR через
`excludeRoute(IpPrefix)`. Сам `GoBackend`, нативная библиотека WireGuard и формат
конфигурации не форкаются.

Системный `excludeRoute()` отсутствует до Android 13. На Android 12 и старше
приложение не применяет дополнение `AllowedIPs` и не подключает второй
пользовательский VPN-движок. На этих версиях split-tunnel полностью выключен на
уровне устройства: `Tic + via_tak`, `Tic + standalone` и Stray продолжают
подключаться как обычный полный туннель без адресных и прикладных исключений.
Интерфейс сообщает, что split-tunnel требует Android 13 или новее, но не
блокирует VPN-подключение.

Домены на устройстве самостоятельно не разрешаются: панель передает готовые
IPv4 CIDR.

Удаленное с устройства приложение исчезает из активного пользовательского
правила при следующем сканировании. Событие удаления сохраняется в истории
панели, но больше не учитывается в текущей агрегированной статистике.

## Пользовательский интерфейс приложения

Настройки split-tunnel относятся к конкретному устройству.

Android-экран содержит:

- выбор одного из двух режимов;
- переключатель «Исключить локальные адреса», включенный по умолчанию;
- поиск по приложениям;
- обязательные исключения с заблокированным переключателем и подписью
  «Исключено настройками Nelomai»;
- рекомендации;
- остальные приложения;
- переключатель показа системных приложений;
- состояние последней синхронизации.

В режиме «Только выбранные приложения через VPN» обязательные исключения
остаются видимыми, но недоступными для выбора.

Если пользователь меняет режим или список во время активного VPN, приложение
предупреждает о коротком переподключении для активного `Tic + via_tak` или
Stray. После подтверждения изменения применяются сразу. При активном
`Tic + standalone` новые настройки сохраняются без переподключения и будут
использованы при следующем подключении через Tak или к Stray.

При недоступной панели настройки показывают последнюю рабочую политику и
ненавязчивое предупреждение об устаревших данных. Подключение не блокируется.

## Локальные сети

Настройка «Исключить локальные адреса» включена по умолчанию. Она исключает
только фактически подключенные физические сети, а не все частные диапазоны
целиком.

Например, для физического адреса `192.168.1.25/24` напрямую направляется
`192.168.1.0/24`.

Сети VPN, loopback и виртуальных адаптеров не считаются локальными сетями
пользователя. Локальные сети:

- определяются перед каждым подключением;
- повторно определяются при изменении физической сети;
- не отправляются в панель;
- при изменении во время активного VPN вызывают безопасное переподключение,
  только если эффективная политика действительно изменилась.

## Привилегированные компоненты

Контракт `TunnelOptions` расширяется версионной политикой:

- режимом приложений;
- разрешенными или исключенными package ID;
- адресными исключениями;
- флагом исключения локальных сетей;
- хешем политики.

На Windows, Linux и macOS helper/service:

1. фиксирует исходный шлюз и необходимые маршруты;
2. создает более специфичные прямые маршруты для исключений;
3. запускает туннель;
4. при остановке или восстановлении после сбоя удаляет только созданные им
   маршруты и возвращает исходное состояние.

Операция должна быть идемпотентной. Повторный `stop`, повторное восстановление
после сбоя и запуск после аварийного завершения не должны оставлять маршруты,
которые ломают сеть устройства.

Решение об активации split-tunnel принимает общий клиентский слой до вызова
платформенного helper. Helper не должен догадываться о режиме по содержимому
WireGuard-конфигурации: он получает split-политику только для
`Tic + via_tak` или Stray.

## Синхронизация

Полная фоновая синхронизация выполняется не чаще одного раза в сутки.

Пока приложение запущено, оно раз в пять минут выполняет дешевую проверку
ревизий. Этот опрос:

- не создает пользовательских задач;
- не создает записи обычного журнала операций;
- не загружает полную политику, если ревизии не изменились.

Обычные изменения администратора применяются при следующем подключении после
очередной суточной синхронизации. Изменения самого пользователя применяются
сразу.

Кнопка администратора «Принудительная синхронизация»:

- действует на все устройства;
- требует дополнительного подтверждения;
- увеличивает принудительную ревизию;
- заставляет запущенные приложения получить полную политику при ближайшем
  пятиминутном опросе;
- остается ожидающей для выключенных приложений до следующего запуска.

Перед переподключением сравнивается хеш эффективной политики. Если содержимое не
изменилось, VPN не перезапускается.

Если в момент принудительной синхронизации активно подключение
`Tic + standalone`, новая политика сохраняется без переподключения: для этого
соединения ее эффективное содержимое пусто.

## Атомарное применение и восстановление

При изменении эффективной политики активного подключения:

1. приложение сохраняет предыдущую рабочую политику и параметры подключения;
2. останавливает VPN;
3. применяет новую политику и поднимает прежний тип подключения;
4. при ошибке один раз пытается восстановить предыдущую политику и подключение;
5. если восстановление удалось, оставляет VPN на старой политике и показывает
   ошибку обновления;
6. если не удалось и применение, и восстановление, оставляет VPN выключенным и
   показывает явную ошибку.

Результат применения отправляется в панель при первой возможности. Ошибка
отправки результата не влияет на соединение.

Недоступность панели никогда не отключает работающий VPN и не запрещает новое
подключение по последней успешно сохраненной политике. Кеш политики не имеет
срока, после которого пользователь искусственно блокируется.

## Административный интерфейс

В настройках приложения панели добавляется раздел «Split-tunnel»:

- глобальный флаг функции;
- список обязательных package ID;
- список рекомендуемых фрагментов имени;
- статистика пользовательских исключений;
- кнопка «Принудительная синхронизация».

Глобальный флаг изначально выключен. Старые версии приложения продолжают
работать без split-tunnel.

Статистика пользовательских исключений содержит:

- отображаемое имя;
- package ID;
- число уникальных пользователей;
- число устройств;
- дату последнего выбора;
- действие «Добавить в обязательные».

Считаются только активные выборы. История выбора и удаления хранится отдельно
для аудита. Продвижение в обязательные выполняет только администратор и
подтверждает действие. После продвижения пользовательские правила больше не
создаются для этого package ID, а прежняя история сохраняется.

Для устройств показываются последние примененные ревизия, время и результат.

## Наблюдаемость

В административный журнал попадают:

- изменение глобального флага;
- изменение обязательных package ID;
- изменение рекомендаций;
- продвижение приложения в обязательные;
- запуск принудительной синхронизации;
- неудачное применение политики;
- неудачное восстановление предыдущей политики.

Пятиминутные проверки ревизии, успешные фоновые синхронизации без изменений и
обычное получение кешированной политики не журналируются как операции и не
создают задачи.

Диагностические сообщения не содержат полный список установленных приложений,
секреты WireGuard или содержимое конфигурации пира.

## Безопасность и приватность

- Полный список установленных Android-приложений остается на устройстве.
- В панель передаются только выбранные пользователем package ID, их
  отображаемые имена, устройство и дата выбора.
- Локальные сети пользователя не передаются в панель.
- Панель проверяет принадлежность устройства текущему пользователю.
- Клиент проверяет версию формата, типы полей, допустимые CIDR и пределы размера
  политики до передачи helper.
- Helper принимает команды только от установленного доверенного клиента по
  существующей модели авторизации каждой платформы.
- Хеш используется для сравнения содержимого, а не как замена аутентификации.
- Неизвестная версия политики не применяется: остается последняя рабочая
  политика и показывается неблокирующее сообщение об обновлении приложения.

## Проверки

### Модульные

- обязательное правило имеет приоритет над пользовательским и рекомендацией;
- обязательный package ID не появляется в рекомендациях;
- сопоставление имени не зависит от регистра;
- Android-политика никогда не преобразует адресные исключения в дополнение
  `AllowedIPs`;
- Android 12 и старше считает split-tunnel неактивным для всех типов
  подключения и не блокирует запуск VPN;
- пустой список блокирует старт только в режиме «Только выбранные через VPN»;
- пустой список не блокирует `Tic + standalone`, поскольку split-tunnel там
  неактивен;
- split-политика активируется для `Tic + via_tak` и Stray;
- технический `route_mode=standalone` у Stray не отключает split-tunnel;
- агрегированная статистика считает активные выборы, а не всю историю;
- удаленное приложение перестает учитываться после синхронизации выбора;
- одинаковый хеш не вызывает переподключение;
- устаревший кеш не блокирует подключение;
- локальные сети не попадают в отправляемые данные.

### Интеграционные

- API не позволяет читать или менять настройки чужого устройства;
- обычная ревизия и принудительная ревизия имеют разное поведение;
- пользовательское изменение возвращает новую политику сразу;
- повторный результат применения не создает дубликаты;
- неуспешное применение восстанавливает предыдущую политику;
- падение helper не оставляет созданные Nelomai маршруты;
- отключенный глобальный флаг сохраняет поведение старых приложений.

### Проверки на устройствах

- оба прикладных режима Android;
- адресные исключения Android через `excludeRoute()` на Android 13 и новее;
- `Tic + via_tak`, `Tic + standalone` и Stray на Android 12 и старше
  подключаются без split-tunnel и без раздувания `AllowedIPs`;
- Tic через Tak применяет split-tunnel, а Tic standalone не применяет его;
- Stray применяет split-tunnel независимо от технического `route_mode`;
- переход `via_tak` → `standalone` удаляет прямые маршруты split-tunnel;
- переход `standalone` → `via_tak` применяет последнюю сохраненную политику;
- обязательные исключения Android;
- системные приложения и поиск;
- адресные исключения Android, Windows, Linux и macOS;
- доступ к локальному устройству в физической сети;
- смена Wi-Fi при активном VPN;
- отключение панели при работающем и при новом подключении;
- принудительная синхронизация с измененной и неизмененной политикой;
- аварийное завершение приложения и helper с последующим восстановлением сети.

## Критерии готовности первого этапа

- функция включается и выключается глобально без обновления клиентов;
- Android корректно применяет оба прикладных режима;
- Android 13 и новее, Windows, Linux и macOS применяют адресные исключения;
- Android 12 и старше продолжает подключаться во всех режимах, полностью
  отключает split-tunnel и не пытается строить дополнение `AllowedIPs`;
- адресные и прикладные исключения действуют для `Tic + via_tak` и Stray;
- подключение `Tic + standalone` не получает split-правила;
- подключение к Stray всегда получает split-правила;
- обязательные package ID нельзя отменить;
- панель не получает полный список приложений и локальных сетей;
- недоступность панели не блокирует VPN;
- применение политики атомарно и имеет проверенное восстановление;
- фоновые проверки не создают спам в задачах и журнале;
- старые версии приложения продолжают подключаться;
- реальные smoke-проверки выполнены на Android, Windows, Linux и macOS.

## Вне первого этапа

- прикладной split-tunnel на Windows и Linux;
- прикладной split-tunnel на macOS;
- автоматическое продвижение популярных приложений в обязательные;
- загрузка полного списка приложений в панель;
- автоматическое отключение VPN при недоступности панели;
- селективные IPv6-исключения из доменных «Фильтров блока».
