# Постоянный Android Logcat и отдельное вложение

## Согласованный объём

Полный доступный Nelomai Logcat своего UID (включая процессы контейнера,
runtime и VPN), до 2 МиБ UTF-8. Не системный журнал всего телефона.
Без нового foreground service, уведомления, wakelock и полномочий READ_LOGS.
Работа в текущем maintenance checkout; push, deploy и установка — отдельно.

## Реализация и порядок проверки

1. `PersistentLogcat.kt`: запуск из общего Application только в процессе брокера,
   один читатель, два сегмента по 1 МиБ. Сначала тесты
   ротации, UTF-8, одновременного snapshot и удаления секретов до записи.
   Файлы в `noBackupFilesDir/diagnostics/logcat`. Android 12+ использует `--uid`;
   старые Android ограничивают непривилегированного читателя своим UID сами.
   UI и активный VPN уже связаны с брокером через `RuntimeSelectionStore`;
   сборщик не добавляет новых привязок. Остальные процессы не ждут его завершения
   и не препятствуют Android freezer. После рестарта брокера журнал дополняется.
2. `DiagnosticUploadRequest.logcat_log: Option<String>`: необязательное поле,
   отсутствует у старых/desktop-отчётов и не выводится в Debug. Ручной отчёт
   читает snapshot через JNI и class loader контейнера; имена JNI сохраняются R8.
3. `AutomaticDiagnostics`: базовый отчёт создаётся как раньше. Фоновый отправитель
   один раз добавляет snapshot и атомарно переписывает pending GZIP перед HTTP.
   Повторные отправки используют тот же снимок; пустой/недоступный журнал не
   блокирует отчёт. Время снимка — первая попытка отправки, не время события;
   при долгой очереди ранние записи могут уже уйти при ротации. Тяжёлое чтение
   и сжатие не добавляются в lifecycle остановки VPN.
4. Панель: необязательный `logcat_log` в существующих manual/background endpoint.
   Обычные поля сохраняют бюджет 512 КиБ, вложение — 2 МиБ UTF-8. Wire ceiling
   учитывает шестикратное JSON-экранирование. Один атомарный JSON, прежние квоты
   и срок хранения, отдельное скачивание Logcat только администратором.
   Проверки: размер, UTF-8, экранирование, redaction, права, legacy и квоты.
5. JVM-тесты приложения/common/tunnel, Rust API-тесты, Android-target compile,
   release R8/build и повторное ревью. Аппаратная проверка после готовности панели:
   холодный запуск, плитка, WG/AWG, ручной и автоматический отчёт, единственный
   читатель и ротация без новых уведомлений.

## Ограничения и порядок распространения

Сначала развернуть панель: старый сервер отклонит неизвестное поле.
Ограничение 2 МиБ относится к текущему журналу и каждому вложению, не ко всему
существующему каталогу ожидающих отчётов. Отправленные автоматические отчёты
сохраняют прежнюю политику: последние три. Файлы отчётов с Logcat исключены из
Android backup. Logcat не удерживает приложение живым, при завершении/заморозке
брокера сбор приостанавливается; при следующем запуске добираются последние 100
доступных строк системного буфера. Маскирование скрывает распознаваемые секреты,
но журнал по-прежнему является конфиденциальной диагностикой.

## Результат локальной проверки 10 сентября

- JVM: 507 тестов, без ошибок (app 68, common 7, tunnel 432).
- Rust: client-api 25, диагностика приложения 36; Android aarch64 `cargo check`
  успешен. Release R8 успешен, класс и статический `snapshot(String)` сохранены.
- Панель: 71 тест и 30 subtests, один PostgreSQL-specific тест пропущен;
  scoped lint и `git diff --check` пройдены.
- Два независимых ревью закрыты после исправления замечаний, включая бюджет
  JSON `null`, расширение текста после маскирования и escaped JSON секреты.
- Новая сборка не установлена, аппаратный end-to-end этой функции не выполнен.
  Push, deploy и публикация не выполнялись.

## Исправление контрольного ревью: Android freezer

Убрано постоянное ожидание `collector.lock`: Android воспринимал ожидающий
foreground VPN как причину разморозить cached-процесс владельца. Сборщик закреплён
за существующим брокером, а не выбирается случайно среди broker/runtime/VPN.
Регрессионный тест проверяет, что runtime/VPN/неизвестный процесс не запускают
сбор, а повторный запуск брокера сохраняет предыдущий журнал. При временном
удалении проверки процесса тест воспроизводит ошибку.

После исправления: 508 JVM-тестов без ошибок, stable AAR и release R8 успешны,
JNI `snapshot(String)` сохранён. Повторное независимое ревью — без замечаний.
Аппаратная проверка freezer не выполнялась; push/deploy/установка не выполнялись.
