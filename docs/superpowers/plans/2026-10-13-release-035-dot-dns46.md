# Nelomai 0.3.5 DoT DNS46 Implementation Plan

> **For agentic workers:** использовать `superpowers:executing-plans`, лично и последовательно, без субагентов. Checkbox отмечаются только после фактической проверки.

**Goal:** NLM-072: собственный strict Private DNS hostname Nelomai использует DNS46 в VPN и обычный DNS вне VPN.
**Architecture:** дополнительный ограниченный TLS вход существующего DNS46 процесса на Tak через Python `ssl`/`socketserver`. Существующий transit-SNAT уже сохраняет source; добавить только точные own-endpoint redirect/INPUT rules на Tak. Public DNS использует существующий upstream exchange без DNS46 allocation/policy.
**Tech Stack:** Python ssl/socketserver/dnslib, existing OpenSSL/systemd, Node/nftables, Python panel, Rust/serde, Kotlin/Svelte.
**Spec:** `../specs/2026-10-13-release-035-dot-and-async-stop-design.md`, раздел A, утверждён пользователем.
**Исполнение:** Native/`executing-plans`, лично после Stop S4. Статус 14.10.2026, 01:59 МСК: D1–D4 реализованы и проверены локально; доставка/аппаратная приёмка NOT RUN.

## Global Constraints

- APP/PANEL checkouts и SHA — как в соседнем async-stop плане. Только 0.3.x; 0.4.0 branch/worktree не трогать, чужие vendor/pycache сохранять.
- Новая сборка запрещена. Code commit/push/version bump/release/deploy/production migration/DNS/cert provisioning/phone install — отдельные разрешённые этапы. Никаких реальных ключей/сертификатов/серверных настроек в этом проходе.
- Собственный hostname `dns.nelomai.ru`, configurable. Advertised endpoints только IPv4, production TCP/853. TLS минимум 1.2, без plaintext на 853, отключения проверки сертификата или пользовательской CA на телефоне.
- DoT default OFF. Ready только после cert/key/hostname/validity/bind/trusted TLS probe. Ошибка DoT не выключает существующий UDP/TCP DNS46.
- Отдельно от plain DNS: 64 TLS connections всего, 8 на observed source, handshake 5с, idle/frame-read 15с, 64 queries на connection, wire frame 1..65535 байт. Query deadline/backend pools существующие.
- Public DNS: 20 queries/sec/source, burst 40, LRU buckets ≤4096. Только обычный QUERY; AXFR/IXFR/UPDATE запрещены. Public source не использует Mapper/SourceMappings/CandidatePolicy/Jool; synthetic ответ не утверждает DNSSEC AD.
- Identity — только observed source, подтверждённый tunnel/source policy. PROXY/ECS/клиентский заголовок не назначает VPN identity. Localhost и неизвестный protected transit не превращаются в другого VPN клиента.
- Только собственные configured IPv4+TCP853 tuples; чужой DoT не перехватывать. System Private DNS не менять; native IPv6 TUN и неизменный сторонний Quad9 hostname вне scope.
- Cert/key читаются из локальных root-managed путей; private key не попадает в panel API/logs/app. Test CA/key генерируются в TemporaryDirectory, не коммитятся.
- Без нового proxy manager, upstream manager, службы, очереди, watcher или репликации mappings «на будущее». Existing upstream policy не заменять; при separately encrypted upstream не вводить hidden plaintext retry.

## Результат ревью по коду

1. `dns46_proxy.py` уже содержит `Resolver.recv_exact()`, `Resolver.exchange()`, `TCPHandler`, `BoundedThreadingMixIn`, отдельные query/probe pools и process shutdown. Удалён обязательный новый `dns46_dot.py` и набор DotConfig/DotLimits/DotContextStore/DotBudget. Несколько локальных transport функций и отдельный bounded TLS server в том же script достаточны.
2. Plain mixin имеет **общий class semaphore 128**. DoT нужен собственный instance budget 64/8; нельзя занять plain budget handshake или принимать TLS handshake в main accept loop. Фрагментированное чтение использует существующий recv_exact с абсолютным deadline.
3. `Resolver.query()` пересобирает DNSHeader/Question и теряет CD/EDNS DO/прочие EDNS данные. Удалён неверный шаг «public через query() с сохранением DNSSEC». Public передаёт валидированный original wire через existing bounded exchange, без второго DNS cache; response flags/EDNS не переписываются.
4. `runtime.js::buildDns46MasqueradeBypassCommands()` уже SNAT-ит **весь** трафик каждого DNS46 peer к его transit source через primary/reserve Tak. Это включает 853. Не добавлять повторный Tic SNAT и не менять `session_nat.js` (он инспектирует session NAT, а не генерирует DoT rules). Own redirect/INPUT belongs в existing `dns46_firewall.js` на Tak; runtime tests доказывают reuse существующего SNAT.
5. `buildDns46SyncCommands()`/`buildDns46ReconcileCommands()` сейчас выключают процесс при нуле peers; это несовместимо с public DoT после Stop. Service enabled = plain peers существуют **или** own DoT enabled. Plain client firewall остаётся закрытым при нуле peers; public listener не исчезает.
6. `syncDns46EgressRecord()` сравнивает только peers: cert-path/hostname/endpoints-only change сейчас потеряется. Добавить validated dot config в existing state comparison/pending rollback. Сертификатный reload — штатный ExecReload/SIGHUP того же процесса, не новый watcher; config/source changes идут через существующий restart/reconcile.
7. Existing sync response содержит лишь `status/peer_count/changed`, `inspectDns46Runtime()` лишь service status/stats. План явно дополняет эти реальные пути trusted readiness; boolean enabled/старый ready file сами не доказательство Ready.
8. Android уже имеет `planVpnRoutes()`/`forcedTunnelRoutes`. Дополнить точными /32, не маскировать DoT endpoints под DNS53 servers и не делать нового route owner. Пропущенные `TunnelPlugin.kt`/background capability wiring добавлены в D4; лишние isolated UI/test layers исключены.

## Review Focus

- Source отозван между keepalive queries: каждый query проверяет действующую allowlist+source mapping, без synthetic ответа чужому source — D2.
- Cert/key swap, failed reload или expiry: last valid context сохраняется, expired context не Ready — D1/D3.
- Slow TLS/fragmented clients забивают бюджет: соблюдаются 64/8/5с/15с/64 без блокировки plain DNS — D1.
- Zero VPN peers, dot-only config change, split/cold/background Start: public DNS остаётся доступным, только own /32 routes, без stale readiness — D3/D4.
- Cached synthetic A после failover: отдельная проверка старого cache на фактическом reserve, fresh lookup её не заменяет — D4.
