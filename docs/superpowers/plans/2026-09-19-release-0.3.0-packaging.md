# Prepare 0.3.0 without republishing stable

## Scope

User-approved steps: fix the macOS CI fixture, package latest 0.3.0 with the
published stable 0.2.20, deploy the already merged compatible panel, then test
Android via ADB. No public release, stable rebuild, agent/peer changes, or
new runtime architecture. Existing signed container and release-set contracts
remain unchanged. Review and diagnosis stay with the main agent.

## Tasks

1. Replace the flaky Python process fixture with the same Rust test executable;
   retain deadlines and process-group assertions. Run repeated and package tests.
2. Extend existing signing/staging/packaging consumers to accept an independent,
   pinned published stable release-set. Test exact preservation, wrong source/hash,
   absence of stable, and actual two-slot Android package checks. Set current source
   version to 0.3.0; keep historical 0.2.20 verification fixtures intact.
3. Update the existing release workflow to download and authenticate stable before
   signing, without publishing. Run relevant Python, Rust, JS and workflow checks.
4. Deploy panel ec6ce12 through its normal self-updater and verify completion.
5. Build a signed candidate and install as an upgrade, never uninstall/clear data.
   Before first Stray connection start concurrent live logs on Android and the
   involved Stray servers, record UTC timestamps, and preserve failure evidence
   before any retry. Test current and stable paths without user-peer mutation.

## Verification / review focus

- Every archived stable ZIP, manifest and signature remains byte-identical.
- Stable source and root digest are independent of latest source/root.
- A missing/invalid stable cannot silently produce a latest-only 0.3.0 package.
- Android links the archived AAR and retains the common VPN service; no package
  uninstall, app-data wipe, additional VPN service, or timeout inflation.
- Test-key builds are not release candidates; hardware upgrade must match the
  installed signing certificate.
- Published 0.2.20 and user-modified vendor submodules remain unchanged.
