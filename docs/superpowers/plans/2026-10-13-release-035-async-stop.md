## Результат ревью по коду

1. `stop_client_connection()` уже без agent RPC переводит сессию в STOPPING через оркестратор и помечает Stop APPLIED. Долгое ожидание находится в `ServiceRedundantConnectionPanel.stop()`: он требует terminal/WARM lease **и session_id=null**. Поэтому нужен явный acceptance ACK, а не новая HTTP-служба или ускорение native close.
2. `stop_redundant_session_in_transaction()` уже замораживает роли, переводит members в CLEANUP_PENDING и VIP в QUARANTINED. Расширить эту транзакцию; удалить обязательный новый `app/client_async_stop.py` и дублирующий Stop handler. Оркестратор сейчас сам делает commit — acceptance и marker должны попасть в тот же commit, не в следующий.
3. `client_operation_fence.py::_operation_execution_lock_key()` намеренно игнорирует operation_id и блокирует **устройство**. Нельзя просто переименовать operation ID или ослабить общий guard. Узкий execution lock конкретного старого member нужен только для detached cleanup; существующий device guard Start/logout сохраняется.
4. Удалены обязательные `cleanup_claim_token`, `cleanup_claim_until`, таймер 60с и отдельный `CleanupProof`. Долговечное work состояние уже есть в member/journal. Для единственного исполнителя достаточно штатного resource-scoped lock и повторной точной проверки владельца; сбой процесса освобождает lock, member остаётся pending. Новый lease/claim механизм допустим лишь если тест докажет недостаточность этого пути.
5. Одной правки partial index недостаточно: старые leases отдельно блокируют allocator, а `retained_warm_lease_reusable()` требует STOPPED всей сессии. Нужны узкие predicates для accepted normal Stop и уже очищенного primary, без снятия revocation/runtime guards.
6. Вызовы inspect, clear, retain WARM, release и pinned restore содержат собственные RPC. Все они учитываются при выносе I/O из locks. Нельзя оставить сетевой WARM/release внутри «короткой финализации».
7. Исправлены пропуски файлов `client_operation_fence.py`, `client_runtime_contracts.py`, `RedundantProductionAdapters.kt`, `TunnelPlugin.kt`, `connection-operation-reconcile.schema.json`. Python fixture validator ручной, на stdlib: добавление JSON schema само по себе его не изменяет.
8. Никаких повторных native-close/WARM/retry реализаций, отдельных client cleanup workers или независимого ревью на каждом мелком шаге. Сохранён унаследованный личный метод исполнения.
