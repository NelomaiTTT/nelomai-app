# Холодный запуск Android — 10 сентября 2026

Проверено на S23 Ultra / Android 16 по беспроводному ADB. VPN выключен,
данные приложения не очищались, авторизация сохранилась. В основе итоговой
локальной сборки — maintenance `606fdd4` и незакоммиченные тайминги запуска.
Это тестовый пакет, не опубликованный release artifact.

## Причина и измерения

Исходный локальный пакет использовал неоптимизированный Rust host внутри
release APK. Gradle release не оптимизирует заранее собранные `.so`.

| Этап | Исходный host | Только host заменён на release |
| --- | ---: | ---: |
| Подготовка файлов | 285 мс | 82 мс |
| `nativeOpen` | 3939 мс | 209 мс |
| `nativeAttach` | 3593 мс | 159 мс |
| Загрузка runtime-библиотеки | 8 мс | 2 мс |

Обе проверки хешей в `CommonHost::open` / `attach_android` сохранены.
Повторное копирование файлов не было основной причиной, его логика не менялась.
Тайминги охватывают JNI-операции целиком, а не отдельные вызовы SHA-256.

В итоговом пакете оптимизированы обе Rust-библиотеки. В трёх холодных
запусках (первый после установки, два после force-stop) WebView начал
загружаться через 1034, 936 и 727 мс от `START MainActivity`.
Это не метрика полной готовности UI. По записи экрана второй запуск дошёл
до «Готово к запуску» приблизительно за 2–3 секунды.

## Проверки

- 445 JVM-тестов приложения и tunnel plugin: 0 ошибок, 0 провалов.
- Stable Android AAR с добавленными таймингами собирается.
- Проверка итогового APK: подпись APK действительна; manifest/payload hashes
  проверены; один slot latest; одна VPN-служба.
- Smoke-проверка: runtime с WebView остаётся resumed не менее 5 секунд.
- После повторных запусков сохранён авторизованный дашборд; в захваченном
  AndroidRuntime-журнале исключений не наблюдалось.
- Туннели в этой проверке не включались; это проверка запуска, не WG/AWG E2E.
- Rust Android release-сборки успешны, но выводят существующие предупреждения
  unused/dead code; чистый от предупреждений Android build не заявляется.

В коде добавлены только короткие Logcat-тайминги без содержимого bootstrap,
токенов и данных аккаунта. Они не добавляют ожиданий и не меняют admission.
Инструкция локальной сборки уточнена: для performance acceptance нужны
`--release` и библиотеки из `target/aarch64-linux-android/release/`.
GitHub release builder уже использует эти параметры. Push/release не выполнялись.
